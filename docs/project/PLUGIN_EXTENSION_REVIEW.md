# 通用插件扩展评审：战斗行动组合与实时交互会话

2026-10-06，**完整设计草案，待共同评审；本轮不实现接口或玩法**。Z招式、Mega与钓鱼/移动判定条只作为检验案例；交付目标是插件可以组合规则及编写实时交互，不能在核心增加机制名称、插件或物种ID分支，也不在默认Gen3包安装现代玩法。

## 外部评审核对：两条结论不成立，公开接口仍有真实缺口

### “Z招式必须无视灼伤”不成立

针对第七世代传统回合制，物理Z招式并不普遍免除灼伤的伤害减半。Pokémon Showdown的[招式派生及伤害实现](https://github.com/smogon/pokemon-showdown/blob/master/sim/battle-actions.ts)中，普通攻击Z招式继承源招式类别；灼伤条件是物理招式且没有毅力，未排除Z招式。特定招式/特性例外不能泛化为所有Z招式。这里引用维护者的规则实现作技术核对，不称为官方卡带源码。

项目[model.js](../../src/engine/model.js)确实直接检查本体status，但“进入分支”不等于“一定减半”：`burn-modifier`将0.5返回为1，整数伤害乘1再取整不会减少。现有[毅力数值规则](../../src/engine/rules/gen3/numeric.js)已经这么做；公开`api.rules.register`也能注册该数值阶段，不需要暂时抹掉灼伤。

真正值得扩展的是**本次行动的来源和作用范围**：现在增强计划不是伤害阶段中的独立规则来源。如果插件想声明“只有这一行动免除某项修饰”，应补行动上下文/作用域，而非因错误Z前提添加`ignoreBurn`专用开关。

### “Mega后本回合不能换人/逃跑”不是普遍规则

针对第六/第七世代传统回合制，Mega随招式选择，不能同时再选手动换人或逃跑作为另一主行动。这不等于进化后整回合被禁止离场：Mega后使用伏特替换仍可离场。[宝可梦官方策略](https://www.pokemon.com/us/strategy/rejuvenate-old-favorites-with-mega-evolution)推荐Mega雷电兽用伏特替换离场并反复触发威吓；参考实现的`runMegaEvo`也没有安装整回合禁令。这里不泛化到其他游戏的同名机制。

项目[BattleActions.prepare](../../src/engine/battle/actions.js)已有`switch-check`，逃跑执行已有`escape-check`；[原生控制状态](../../src/engine/rules/gen3/control-states.js)已使用它们。不能仅看`switch()`的实际换人段就断言“没有检查位”。[replacementRequest](../../src/engine/battle/replacement-requests.js)用于活着的个体产生的中途接替请求，并非仅倒下强制换人；也不能拿它冒充行动禁令。

但**内部有检查阶段不代表公开插件可完整接入**：插件回调接收冻结值，禁止`apply`，目前只能返回数值或注册操作，直接写`c.allowed=false`不在公开合同内。`ruleContext`也未完整投影forced/接替原因。因此真实缺口是有原因和范围的行动许可返回值，能够区分手动换人、招式自换、被迫换人、倒下接替和逃跑；规则包决定限制范围，不能为Mega一律加锁。

### 形态持续能力已部分存在

[CreatureForms.restore](../../src/engine/creatures/forms.js)已按`clearOn`决定离场/倒下是否清除注册形态；缺省或空数组不会清除注册形态ID，战斗结束清除battle形态。旧稿“离场就恢复”的概括过宽。应补的是选择/提交时机、资格投影和特性来源转换，不重建形态持续系统。

## 当前结论与代码证据

现有框架可以做“限次替换招式”与“临时形态切换”的简化玩法，尚不能仅靠公开插件API准确组合完整的现代战斗机制。缺口主要在行动和时序合同，资源素材/威力表则属于内容。

这里不把HP缩放、全局永久限次、任意行动类型或动态卸载列为Mega/Z必须修复项：前两例不证明这些需求。已有特性投影、形态清理、PP回滚、UI槽、表现注册也不重复建设。

## 共同边界：插件定义业务，宿主持有执行权

战斗扩展已有行动计划，实时交互新增轻量会话所有者；两者复用注册/schema、冻结投影、来源与权限、表现及结果提交边界，不把回合战斗塞进每帧会话，也不合并成一个能任意写所有领域的事件总线。

插件拥有资格、内容、业务阶段、有限政策和画面数据。宿主拥有实例身份、阶段顺序、时间、输入采集、随机流、资源、锁、提交凭据与释放；库存/队伍/地图等仍由原领域持有。查询与表现不能写世界，业务运行态不每帧写extensions存档。

复用`runtime.evaluate`禁止纯回调dispatch/事务，注册原子验证schema、引用、命名空间、回调类型和允许结果。新增capability版本查询，要求能力不存在时启动拒绝；保留旧API，不让一个新字段被旧宿主静默忽略。

现有插件是受信任JavaScript模块，这些是协作与校验合同，**不是操作系统沙箱**。冻结context不能技术上阻止模块自行读Date或访问浏览器；只从宿主获取时间/输入/随机由作者合同、示例和确定性测试共同约束。

## 战斗方案：增量扩展已有所有者

以下是**拟议合同方向，名称/字段不属于当前可调用API**。保留现有Action、Round、CreatureForms、MoveExecutor、Checkpoint及UI/策略端口；不增加第二套战斗内核。

### 1. 行动附加选择与受控提交点

在现有move选择中携带一个或多个已注册的附加项引用，而不是先执行免费的独立命令。候选查询返回资格、不可用原因、目标模式、费用、额度以及生效点；只传注册ID/合法参数，不能由UI发送原始属性覆盖或内部计划。

宿主将选择编译成只读执行计划，并绑定actor UID、席位、源招式槽和本轮决策修订。再次选择替换原计划；单席位取消释放自己的预留，全轮取消清空全部预留；未确认不改形态/PP/库存，不发已生效事件。多席位与AI在同一个决策表中预留，不能分别承诺同一份额度。

初轮只开放三个固定提交点：`beforeOrder`（所有必需选择确认后、普通队列排序前）、`beforeAction`（轮到行动并验证原actor仍在席位且存活后、正常发动检查前）、`moveStart`（正常管线已能发动本次招式、进入开始提交段）。不能自行插入任意阶段或改变Round关键顺序。允许的效果和费用提交点由注册器验证，非法组合启动拒绝。

这让“先切换有效状态，再排序/行动”与“只增强本次招式”共享选择合同，却保持自己的生效条件。无法行动时是否仍发生前置形态切换，取决于其提交点；不能沿用一条“睡眠就统一不消费”的隐藏假设。

生效时间与排序取值时间独立：排序可用选择时快照或生效后投影，由规则包声明；多个beforeOrder转换的特性触发顺序由批次政策规定，不能靠插件注册顺序凑出结果。附加项失效时主行动继续/失败使用有限声明政策，不静默换招或绑定新上场个体。

### 2. 通用资格与额度预留

资格context同时提供基础身份和完整有效投影：base/effective creature、sourceMove/当前招式槽、controller/alliance、受声明的controller capabilities、天气及必要战场状态。全部冻结、同步、可重复求值；只读回调不能扣费、取随机数或提交命令。控制者能力由应用/规则包建立受校验投影，不开放整份世界存档。

形态和招式附加项都引用同一个战斗所有者管理的`scope + subject + key`额度池，支持独立key与显式共享key、容量、互斥组和预留。额度服务负责reserve/release/commit/checkpoint，形态记录继续由CreatureForms拥有。装备条件默认只检查，不消耗；库存费用由Inventory负责；原槽PP仍由MoveExecutor支付，不归插件store。

每个提交点复验UID、资格、费用和引用，不能退而使用另一招式或换到另一只精灵。额度消耗发生在对应的真实生效提交；开始后未命中/被挡不退回，未开始则释放。内部异常恢复当前尚未公开的提交单位中的领域、账本、待选、随机数和事件，不能倒退其他已成功行动或已提交的前置状态。正常未命中不是内部异常。

### 3. 有边界的招式派生与判定政策

保留已注册替换招式白名单，追加受校验的“从源招式派生”计划，初轮只允许必要字段：威力、属性、类别、目标、命中政策、优先级来源及效果定义引用。每个字段区分继承、固定值或受限纯查询；不存在任意函数改战斗对象、任意JSON合并或动态注册招式。

伤害类别变成声明政策：默认继续Gen3按属性选择，独立规则包才启用按招式/计划选择。排序优先级与招式判定所见的优先级分别取自明确政策，避免“替换为另一招式”顺带改变本回合行动顺序。

将保护判定独立为通用防御交互结果，允许block/pass/scaledDamage等有限结果；免疫、隐藏目标、准确率各有独立政策。缩放必须进入正常伤害管线及其取整位置，不能靠`bypassHitChecks`跳过全部检查，也不能在UI直接扣HP。

本次修饰来源绑定plan/action ID、actor UID和阶段，结束/失败后自动移除；数值政策继续现有阶段，例如自定义本次免除灼伤倍率只返回1，不改变status。不能泄漏到别的精灵或下一次行动。

额外效果通过已注册效果/op与生命周期组合，明确是在原行动前/后、失败时是否仍生效、按行动一次还是按目标重复。保留原招式的蓄力/硬直等行为须显式选择兼容的策略，不能直接解除当前多回合替换禁令。首轮遇到现有op表达不了的语义再补窄op，不一次开放任意自定义执行函数。

### 4. 有效状态切换生命周期

复用CreatureForms投影，增加通用资格及明确的transition提交事实。特性变化区分“旧来源解除→新来源附着→状态切换触发”与“实体入场”，不能一律重播全部entry逻辑。同一只精灵的形态、临时能力覆盖、压制状态及恢复须有明确优先级，避免两个插件互相覆盖。

形态记录、来源UID、持续范围、离场/倒下/结束策略仍由同一服务持有；换人恢复能力来源但不恢复已用额度。世界持续状态才走现有保存合同；战斗临时状态不进入存档。表现按提交事实播放，动画失败不会重新执行规则或支付费用。

### 5. 行动许可的有限返回值

复用switch/escape等检查入口，公开冻结的来源、行动种类、reason，以及有限`allow/deny + reason`结果。UI候选、prepare与执行共用判定；deny和保证逃跑等竞争政策由宿主明确优先级。手动、自换、被迫、倒下接替分别判断，不让一个全局锁误拦救场。只对实际需要的阶段开放结果，不允许任意改context。这是通用控制状态扩展，不作为Mega必需补丁。

### 6. 战斗组合验收

先交付行动附加选择、固定提交点、共享额度与完整资格/状态切换，再补招式派生、防御交互和许可返回。每阶段公开类型、注册校验、查询、命令、失败恢复及一个真实组合例一起交付，不能只列API名称或单测一个类。

用三个没有现代机制专名的最小插件夹具验收：

- 战术姿态：随本轮招式选择，排序前变能力/特性；取消完全无副作用，重新选择正确释放，换人/结束恢复，双席位争用只允许一方。
- 蓄能攻击：继承原招式类别/优先级、派生威力，原槽PP一次扣除；普通防御与部分减伤独立，免疫仍拒绝；睡眠/目标离场/后段异常结果明确。
- 支援附加效果：原行动保留并附加注册效果，按行动仅一次，失败政策明确；AI与UI查询/取消消费相同合同。

Z/Mega只作为最终覆盖检查，规则包另行确定第六/第七世代行为和数据；通用例通过不等于完整现代机制已完成。默认Gen3原结果不得改变，也不恢复已删除产品玩法。

控制状态另验证手动/自换/强制/倒下接替/逃跑的不同许可，UI与执行一致；不是测试“Mega整回合禁止离场”。

## 实时交互方案：宿主驱动的会话

### 1. 可复用的现状

因此新增会话所有者和接线，不重写绘制系统、设施规则或存档系统。

### 2. 注册和生命周期

拟增InteractionSession领域服务及最薄应用适配器，实例绑定owner、定义版本、源场景/目标、输入焦点和结果提交资格。插件业务phase是普通JSON状态；宿主生命周期为`running → paused/running → finishing → completed`，另有cancelled/failed。插件自己决定抛竿、等待、咬钩的转换，宿主持续推送驱动，不读取业务phase名字来调度。

拟议注册包含参数/状态/结果schema、语义输入profile、init、step、view、注册画面模板、完成处理和有限暂停/取消政策。以下只说明形状，**不是当前可运行API**：

```ts
registerInteraction({
  parameters, state, result, inputs,
  init(startContext, params): State,
  step(state, { clock, input, random, context }):
    { state: State, terminal?: { outcome, result } },
  view(state, { viewport, interpolation, reducedMotion }): FrameData,
  visual: registeredFrameTemplate,
  completion: registeredCompletionHandler,
});
```

start由公开命令、fieldAction或设施动作发起，检查资格、参数、场景、资源和并发，取得租约后开始驱动；失败释放租约/预留。首版一份控制输入只给一个会话，不加入后台并发小游戏。父剧情/设施可明确交接子会话所有权，不能因为父流程自身busy把子会话暂停死锁。

init/step/view同步执行，状态/结果经schema、大小和引用检查；不能接收game、DOM或存档可变对象。业务数据由插件返回，实例版本、时钟、随机流、修订、生命周期及凭据由宿主持有。

### 3. 时间、帧驱动和回放

接现有app帧循环：采集输入→推进逻辑→生成画面。插件不创建RAF、wait循环或键盘监听。clock给出单调的会话逻辑时间、tick、dt和elapsed；外部帧时间只输入宿主适配器，不由插件读取系统时间。

推荐固定逻辑步长（初值60Hz，实现时定案），显示可插值。每次step的dt相同；相同按tick排列的输入在30/60/144Hz显示应得到同一业务结果，计分不依赖显示帧数。暂停冻结逻辑钟，恢复重建时间基准，切后台十秒不能算十秒漏按。

短抖动有限补步，长停顿显式暂停/重设基准并记录；不能无限追帧，也不能默默截断dt仍声称完整回放。输入边沿按宿主时间映射至逻辑tick，保持顺序；截止时间与同tick输入的判定顺序是宿主合同的一部分。

测试完全注入时钟。回放记录定义/规则版本、初始上下文、随机种子、步长、有序输入与暂停事件，不能只记最终图像。世界日夜/种植钟与会话逻辑钟分开；世界/NPC暂停按宿主活动政策，默认排他小游戏暂停玩家移动与竞争业务，会话本身继续运行。

### 4. 持续输入与瞬时边沿

宿主统一动作快照提供held、pressed、released和带顺序号/tick的edges。插件声明left/right/confirm/cancel等语义动作，宿主映射键盘和触控。多来源合并，一个键松开不能清掉另一来源仍按住的同一动作。

只在状态变化生成边沿，键盘repeat不重复pressed。一帧之间按下又松开，两个边沿都保留；pressed/released可同时出现，edges决定先后。左右同时按下的业务政策由插件定义，不沿用现有单一held方向的隐式优先级。

会话取得排他输入租约后，方向不再同时移动主角或导航战斗菜单。失焦、隐藏、触控取消和结束清held，并生成可记录的释放/暂停事实；恢复不得继承幽灵按键。AI/测试注入同类输入走校验入口，不伪造DOM事件或调用step。宿主保留返回/取消与可访问操作入口。

### 5. 动态画面提交

使用`view → FrameData → 宿主绘制`，不返回LayoutNode或写HTML/CSS。view只算竖线位置、区间宽度、颜色、数值与已登记资源引用；宿主验证有限值、结构及数量，送入现有field/交互Canvas层。

首轮增加动态帧数据采样/模板连接口，复用已有绘制宿主。第一套模板提供rect/line/text/meter及必要注册sprite节点；宿主统一坐标、裁剪、像素缩放、资源句柄和层顺序，其他图元按真实例补齐。旧presentation.draw保留兼容，新业务作者可只提交数据。

VisualTimeline继续管有限动画，其duration或reducedMotion完成标记不能决定小游戏结束。稳定挂载，不每帧重建DOM/Canvas或重启时间线；从实时会话快照取数据，不拿挂载时冻结context假装持续状态。世界定位图形走宿主坐标投影，首例用屏幕覆盖层即可。

view纯查询，不取随机、不发事务、不修改业务状态；重复渲染、低帧率或reducedMotion不改变判定。绘制失败暂停或有原因地失败，避免玩家看不到画面仍被计时；已提交结果不重发。宿主提供状态文本/键盘操作，但不另外搭假游戏页面。

### 6. 随机与有界运行

宿主提供会话独立的有种子随机流，只在init/step使用，资格/view不取随机。成功start才分配种子，start失败恢复；合法取消不倒退其他领域已使用的世界随机流。完成提交失败重试使用冻结结果，不重新抽奖。

限制状态/帧大小、每tick输入/随机量、图元和并发数；回调不能返回Promise。异常/非法输出有明确失败及租约清理。同步主线程JS不能可靠抢占死循环，操作计数不等于强隔离；首版仍按受信任模块设计，不为这次扩展引入Worker/沙箱。

### 7. 结果通过原领域安全提交

step返回terminal只是请求结束。宿主冻结最终状态/结果，校验resultSchema，进入finishing并停止step；保持世界/输入租约，UI不能传成功=true、物种或奖金来伪造完成。只有宿主保存的结果凭据可以结算。

宿主调用注册的同步完成处理器，提供冻结开始上下文和真实结果，复用PluginRuntime事务与声明权限的intent。已有reward/createMonster等按原校验提交；插件持久数据、领取ID和世界结果同一提交。新运行态另设检查点：[StateCheckpoint](../../src/engine/state-checkpoint.js)只覆盖JSON存档图和相应RNG，不能假设已覆盖会话、租约或任意服务。

结果要改地图/启动遭遇等现有intent未支持的领域，则补**受限的完成计划适配器**：走WorldState.prepare/commit、EncounterTickets/遭遇等原所有者，限制owner、源场景、目标和操作。准备阶段不能产生外部副作用，参与者有相应恢复或原子提交保证；不开放任意core命令列表，不把异步battle.start塞进同步插件事务。

钓到遭遇是受控后续票据，不等于直接createMonster入队。先确认票据/领取记录，再由应用执行一次正常遭遇/战斗；后续演出失败恢复已确认票据，不再次结算。哪些领域适配器首轮提供由真实例决定，不能把尚未接线的服务称为可调用。

提交复验身份、场景政策、涉及的世界修订、库存/队伍容量。容量不足等可恢复失败保留同一结果，有限retry/cancel；内部异常恢复本次提交。只对持有实例内部凭据的完成路径开放busy门禁，不先解锁再普通dispatch，也不给插件ignoreBusy。重复完成返回已有回执，不重复扣费、发奖或开战。

成功事实公开后表现不再决定奖励；成功/取消/异常finally统一释放租约和输入。强制场景变更、父会话结束和页面关闭有幂等清理；普通失焦按暂停政策，不能误当成奖励结算。

### 8. 保存、费用和取消政策

首版**不承诺刷新后接着玩当前小游戏**。中间状态瞬时，save/export/load/reset和插件配置切换复用并扩展设施/忙碌保护；自动保存可延后至结束，原SaveStore合法性、原文及多页面冲突保护继续有效。暂停、输入回放和注入测试不依赖跨刷新恢复。

若之后需要活动中存档，另交付有版本的状态/时钟/RNG快照和租约重建，不是把运行对象塞进extensions。存储失败报告当前结果已提交但尚未保存，不能因此重复结算或覆盖冲突存档。

start/success/failure/cancel费用明确声明。默认预留、结果提交时支付；确需入场扣费走独立合法提交，取消是否退费使用明确政策，失败恢复不能抹掉已提交入场费。

稳定领取ID/回执随世界结果进入同一份可保存状态，内存Set只保证当前运行一次性，不能宣称跨刷新幂等。崩溃恢复上次成功保存的世界检查点，未保存结果不承诺持久存在。

### 9. 完整验收闭环

| 例子/路径 | 必须证明 |
| --- | --- |
| 定时窗口 | 宿主推进业务阶段；暂停十秒不漏判；截止tick和输入先后明确；同seed/input在不同显示帧率及回放下同结果 |
| 移动判定条 | held连续移动；pressed/released及同tick双边沿；键盘触控合并；失焦无粘键；主角不同时移动；帧数据实时绘制 |
| 世界结果 | 真插件start→step→terminal→事务→原领域→保存/重载；伪造结果拒绝；重复完成/后续票据不重复；容量/修订失败不重抽；异常恢复 |
| 清理保护 | 成功、取消、异常、强制换场景、父会话结束、关闭页面都释放；保存/重载/配置切换不绕busy；存档冲突和缺插件沿原保护；绘制错误不盲计时 |

真实按住/松手、触屏、视觉节奏、可访问性与听音由用户实机验收。遵守现有不使用Computer Use操作游戏的边界，不将未做的浏览器验收写成通过。

## 合并实施顺序与共同评审的取舍

建议**扩展现有battleAugments与行动计划**，复用形态服务，避免新建一个可以包办所有领域的插件事件总线。首轮限制在招式附加项，任意新增行动类型暂不开放。新查询可先并行提供；既有即时`kind:form`作为明确的即时形态操作保留，新组合能力不复用它的选择时提交行为，避免静默改变已有插件。

核心必须掌握阶段顺序、来源身份、资源支付及回滚；插件掌握资格定义、形态/招式内容、额度key与声明政策。`forms.used`向统一额度迁移时保持现有oncePerController语义，并针对二者并存/取消/失败补证明。额度池key要按所有者命名空间校验，跨插件共享需显式声明依赖/授权，不允许偶然拼出同一key抢占额度。

建议两条线增量交付：

1. 实时R1：会话注册/生命周期、时钟、输入与焦点、帧数据模板、一次性完成事务；交付移动判定条真插件，完成→已有reward intent→保存/重载闭环，错误/取消释放一起交付。
2. 战斗B1：附加选择/取消、三个提交点、共享额度、有效资格和状态转换；用战术姿态完成一轮，保持旧接口兼容。
3. 战斗B2：派生招式、行动修饰作用域、防御/效果组合；许可返回结合控制状态例验收，不因错误Mega评审优先加锁。
4. 实时R2：接现有fieldAction/设施入口，补首例需要的世界或遭遇完成适配器；等价证据完整后逐步迁移原生钓鱼驱动，保留Gen3业务政策与输入节奏。
5. 内容覆盖：如之后要求Z/Mega，再固定世代规格与数据，独立规则插件验收；通用例不代表现代玩法完整实现。

接线落点是现有extensions/contracts、battle服务、app/FrameApplication/BrowserInput、表现适配器，以及必要的新会话领域服务和薄应用适配器；app只装配。实现时按真实职责建文件，不预先铺空目录，不引入dist/复制构建。持久数据确实改变才迁移，每阶段同时交付类型、注册校验、实际装配、查询/命令、生命周期、针对性证明和文档。

推荐首版：排他输入、固定逻辑步长、中间状态不跨刷新恢复、有限提交点和注册效果。战斗额度、输入租约和世界领取记录各归自己所有者，不合成跨领域万能账本。业务纯状态推进，画面用数据模板，世界结果持宿主凭据提交。

上述新增字段、迁移与接口均待共同评审后实施。本轮只更新评审文档，未修改战斗、输入、会话、绘制或存档实现。
