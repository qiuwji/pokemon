# 工程化需求与验收顺序

来源：2026-10-04用户的基建清单及附件；随后明确优先完成内容拆分，再推进其余工作。当前完成状态只维护在[STATUS](STATUS.md)，证据只维护在[VALIDATION](VALIDATION.md)。评审中的数量/行号是历史线索，执行前以实际代码核对，不重复实现已有能力。

## 第一批：内容拆分与可复现读写

- C1–C4：分类目录与清单；地图属性/密集网格分离，可定位、可评审。
- C5–C7：静态内容、插件内容和测试夹具边界清晰；统一内容装配入口。静态原作npcs与运行时elements的共同合同另需后续推进，文件拆分不冒充对象统一。
- C8–C10：文件/字段/引用完整性；缺失地图和script明确分类；真实图集尺寸与索引校验。
- C11–C14：迁移全部现有读取/内容写入入口；所有新文件入库；相对部署路径；不增加旧格式回退。
- 导入器写入范围声明、候选校验、只改有变化的文件、预演不写、失败恢复。完整工具参数化和生成器重组仍属于下一批。

## 第二批：生产隔离与脚本工具链

附件P0逐条复核：防覆盖/越权写进化、悬空/重复warp、测试地图/免费命令隔离、terrain语义一致、键盘按钮可达。不得把已有地形修复或已通过输入证据重新算成新增实现。

脚本清单的12项：索引；只读预演；分类组织；修四个坑；统一源路径；合并重复解析；统一生成标记；字段所有权；依赖检查；导入结果/遗漏校验；选择参数化；本地化数据独立。验收要求从任意目录执行，在缺依赖或未知引用时写前失败，并能以临时目标重现输出。

## 第三批：自动质量保护

自动流水线；check接文档；test接示例；lint/格式；分阶段扩大JS类型检查；覆盖率；强化依赖/状态写入/随机数守卫。避免在同一流水线重复跑等价全量。断言真实结果、失败回滚和资源清理，不用删除断言/skip/吞异常换取通过。

## 第四批：对话、内容和插件管理

D1–D6：完整NPC机制、逐行说话人、立绘表情、插值、条件台词、可保存历史。D7–D11：选择/分支、条件可见/禁用原因、领域后果、默认与超时。D12–D16：数据内容、可配置告示、引用分类、简写、键盘/触屏/reduced-motion。已有choice/if机制应演进，不另外复制规则到文字播放器；原作台词补齐单独验收。

插件不再逐个硬接app；进一步完善配置/依赖/权限/生命周期和可读错误。区分业务、示例和测试，删除无用文件前核对实际消费者与存档依赖。基础NPC与插件elements的运行时合同需要统一，不能只凭同属JSON宣称一致。

## 第五批：核心债与文档一致性

Gen3规则/本地化与通用核心边界；完整/部分注入合同；领域政策单一来源；必需规则不静默跳过；保存和资源错误可定位；资源降级策略统一。按证明过的缺口局部改，不以行数估计驱动重写。

文档按稳定工作规则、接口/工具操作、动态状态/证据分工。API与脚本清单可生成部分从代码提取；示例可执行、链接可检查；接口变更同次更新规格/Skill/测试。自动校验不代替语义评审。阶段记录复用未受影响证据，最终做一次系统回归。
