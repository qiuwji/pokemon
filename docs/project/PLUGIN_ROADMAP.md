# 插件扩展能力评审与后续工作

2026-10-03收到外部评审，下文保留逐项核对与演进方向。最新范围改为框架与代表例交付，按[STATUS](STATUS.md)补真实接口缺口，其余现代玩法和完整业务移交[插件Skill](../../skills/emerald-plugin-authoring/SKILL.md)。评审文字或注册数量不是实现证据。

## 领域扩展

- 形态：核对有效 HP 与当前 HP 的缩放/恢复、个体派生类型、动态招式映射及共用 PP、回合期限、物种通配资格、世界范围的限次持久化。优先让这些能力成为可声明的形态政策，避免为 Mega/极巨/太晶各自复制领域状态与恢复逻辑。默认 Gen3 规则保持 HP 不变，现代机制由独立插件启用。
- 战斗格式：核对现有多联盟/控制器/席位的真实能力。注册格式描述席位、排列、可选目标与行动政策；布局消费同一只读座位模型。三打的距离与轮盘的轮换需要独立政策，不能仅增加格式字符串。
- 环境：天气、场地、空间分别为不同生命周期/作用范围的规则；电子场地、魔法空间、戏法空间不能当成天气名称加入雨晴表。扩展定义同时约束逻辑、事件、保存和表现。
- 阶段：固定阶段顺序仍由结算内核掌握。先用现有通用时机组合新规则；真实缺少的前后结算节点再定义明确合同和排序，不能允许插件随意重排关键不变量。
- 育成：遗传步骤可配置、来源与结果可查；Gen3 为默认政策，后代传球/跨亲本蛋招式等属于版本化规则包。
- 移动：2D 网格是本工程明确的世界合同；基础/加速模式名称可由内容配置，不因此重写为任意几何引擎。

## 表现扩展

- 战斗演出：注册语义事件的演出处理/阶段，形态切换通过同一合同验证；多击、蓄力与未命中需要可选择分支和多段轨迹，不在导演中写现代机制名称判断。
- 动画轨迹：关键帧、具名缓动、条件分支和参数 schema；计时与渲染分离，缩减动态效果模式保留完整语义。
- 场景：场景注册与对应 renderer 注册必须配套。导演负责生命周期/参数，不负责具体画法；适配器选择可用的 Canvas/DOM/SVG 渲染能力。
- 环境/转场：具名注册表、开始/更新/结束/清理合同。避免可注册定义却必须修改适配器才能显示的新假扩展点。
- 多渲染目标：效果声明所需能力；各宿主适配器管理资源与清理，游戏领域不读取 DOM。

## UI 扩展

- 宿主插槽：注册与声明具体页面区域，队伍/背包/商店/战斗都应能挂接入口与内容；未知插槽在启动时失败，不静默消失。
- 布局：增加 input/checkbox/radio/slider/tabs/list/table 等可访问控件及基础像素样式 token。renderer 和控件 schema 成对注册；限制在本项目可信 JS 模式的明确边界，不声称第三方沙箱。
- 既有页面：提供具名区域与类别提供者，支持添加、隐藏与替换的冲突/排序政策；背包分类、详情页页签和战斗附加操作是组合验收锚点。
- 主题：具名字体、间距、边框、尺寸、动画时长 token；像素风默认主题与缩减动态效果政策保留。不要将任意 CSS 字符串散入领域数据。
- 对话/模态：可注册对话类型与结果 schema，取消、焦点、输入锁与导航由 shell 统一负责。
- HUD：默认内容也应通过同一个组件/槽合同组合，显式允许隐藏/替换，监听查询与事实事件；不复制一份金钱/队伍状态。

## 验收与优先级

优先补经业务实例证明的公开接口缺口，按“复杂 UI 模组”和“形态演出模组”两个组合实例验收。内容作者只能修改插件/内容目录，操作经命令、状态经所有者保存、表现只消费事件；要求卸载/重载清理正确。每一项记录已实现未验证或已验证及失效条件，不在每轮重复全部测试。

这些现代扩展不能充当完整绿宝石的机制验收；原作设施、地图、剧情与音画仍有各自的内容范围与验证依据。

### 1. 遇敌渠道与接触合同

2026-10-04首轮合同已实现，实际API/默认政策/不支持项以[遇敌与接触](../engine/world/ENCOUNTERS_AND_CONTACTS.md)为准。下面描述长期目标；当前支持bump/request、单体野生战斗和固定结算释放，重叠触发、任意结算策略还不是现有API。

将原作默认暗雷作为规则包中注册的策略，宿主负责步进/进入/离开/接触这些标准时机。插件通过明确渠道政策替换或禁用 `step` 遭遇，不能靠改rescued旗标、能力倍率或天气规避。禁用在抽样前判断，不能仍消费一个“概率为零”的随机数。捕捉、钓鱼、碎岩、训练家视线与剧情战斗各自保有渠道，禁止一个模糊开关意外关闭全部战斗。

接触事实描述 subject/target、所在格、实际高度、尝试方向、接触种类与步骤标识。支持玩家撞到实体、实体接近玩家和重叠触发的显式政策；持续按键去重，不对不同高度、墙后目标或预约中的实体发错误接触。先提交移动/接触事实，再交给受控行动请求；不借用StoryRunner，也不从绘制函数发起战斗。

公开只读格子/占位查询与当前地区有效遭遇表查询；按地图元数据与注册条件选择真实表，不复制encounters数组。抽样和野生个体创建归遭遇领域，使用宿主有种子的随机源，并清楚区分“选种类/等级”和“生成个体”。插件声明抽样需求，不能在只读规则或表现中调用Math.random。

战斗请求接收领域签发的一次性遭遇令牌。令牌关联生成个体、Actor和所有者；资格与战斗可用性在消费时复检，重复接触不会开两场战斗。失败、逃跑、击败、捕获、离图和重载后的释放/删除由明确政策处理。Actor UID、宝可梦UID与令牌ID不可互换；精灵数据只有一个领域所有者，不塞进Actor.data再复制一份到队伍。

### 2. 可插拔外观，不改变移动与碰撞

拟增外观定义与外观解析接口：声明已注册资源/图集、姿态帧、锚点、层级和可用移动模式；身体、衣服、配饰是有规则的图层组合。默认绿宝石资源也经同一解析器，逐步移走渲染器内的Brendan/物种资源命名分支。

玩家、持久Actor和静态对象通过身份选择合法外观；受控命令只修改外观选择及schema参数，碰撞、速度、位置、物种和招式不变化。临时视觉覆盖与持久换装分开，临时覆盖使用租约并在结束释放。资源缺失、姿态缺失与互斥图层在注册或预检时明确拒绝；静态降级是显式资源政策。可见精灵插件组合species与外观模板，而不是更换移动模式冒充换装。

### 3. 统一相机与视口变换

由相机服务拥有默认跟随、焦点、缩放、逻辑视口及配置，renderer仅消费视图。插件申请受控视图配置/临时租约；剧情临时焦点优先，结束恢复先前配置，不能两个插件互相写同一个point。未知配置、非法缩放、冲突优先级和断开的地图区域需明确处理。

绘制、地图裁切、连接地图可见性、鼠标坐标逆变换、光照和粒子都共享同一个逻辑像素到屏幕的投影；320×224仍作为绿宝石默认配置，不能散落为算法限制。缩放只影响呈现，不能改变一步16逻辑像素的网格规则。若以后换3D画面，应更换渲染适配器并提供资源，不给2D相机参数伪装“已支持3D”。

### 4. 环境层与可见性政策分开

环境表现注册具名层、排序、参数schema、开始/取样/销毁和渲染能力：天气雾、灰尘、雨、局部光照等可组合。逻辑天气与视觉雾不是同一状态；装饰迷雾不能改变遇敌与战斗规则。沿用纯时序、无表现随机数、reducedMotion及资源释放。

需要战争迷雾时另注册可见性政策，读取地形/遮挡物/光源，返回当前可见格；探索记忆由自己的领域状态保存。是否隐藏Actor、是否允许远程选目标由消费端政策明确，不让黑色遮罩决定游戏规则。光照已有半径遮罩可复用，但不是探索记忆仓储。

### 交付顺序与验收

先遇敌渠道/格子与表查询/接触/令牌；随后外观，再统一相机，最后环境层与可见性。每组交付公开类型、一个独立小插件夹具、失败行为测试和作者指引。代表测试可以验证“某渠道禁用时连续步行不抽样；接触令牌只启动一次战斗”，不提供完整按10格生成、寻路野生精灵或换装商店业务。

组合验收由测试插件只使用公开入口完成：按参数选择一批合法草格，抽样并关联动态Actor；未接触不进入战斗；接触可请求一次遭遇；修改外观不改变移动；更改可见格数仍能正确点击和衔接地图；雾与雨/照明可叠加，保存后探索记忆一致。不得修改测试守卫让示例导入application或adventure绕过接口。

这一组之后继续已有的逐字对话、详情帧播放器、剧情演出核对和插件Canvas目标。可选秘密基地/真实玩家联线仍先定义领域合同，完整业务内容由后续Skill推进。
