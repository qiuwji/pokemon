# Mod 扩展审查与后续方案

2026-10-06，依据当前工作树。本文记录审查结果、已修部分与待审设计；不能把“方案”当成实现。验证事实见 STATUS 与验证目录。

## 核心目标：关闭插件后继续原来的冒险

用户要的流程是：本体新游戏 → 启用插件并保存 → 关闭插件 → 同一份主线、队伍、背包和时间进度仍可继续、仍可保存。只保留一个必须重新安装插件才能打开的原文件，不满足目标。

审查时有两种情况；当前执行结果见下文及存档合同：

- 只有页面、规则回调或自有记忆的插件：未声明硬内容依赖的旧记忆已经可以留在 `extensions`，关闭后不执行。`tests/plugins.test.js` 的 `Plugin memory survives` 覆盖这部分。
- 存档实际引用插件地图、道具、物种、移动模式、形态、Actor、世界对白等：`save-contract.js` 拒绝缺依赖；`SaveApplication` 保留原文并暂停覆盖，但启动的是新状态，不能接着原来的进度玩。这是本轮已修复的旧行为；现在通过领域暂停保留内容并继续原冒险。

### 已落地的最小分层设计

保存仍只有一个所有者，不把卸载判断散到地图、战斗、UI 中。增加一个**存档内容解析阶段**，由 SaveApplication 协调；各领域提供小的内容暂停/恢复适配器。

| 部分 | 负责什么 |
| --- | --- |
| SaveStore | JSON、版本、存储冲突和写入；保留读取失败与损坏的分类，不处理宝可梦或地图规则。 |
| 内容依赖解析器 | 比对已启用目录与存档引用，产生明确的缺插件清单和领域处理计划。不能仅删除 `contentDependencies`。 |
| 各领域适配器 | 识别本领域引用、提出可继续玩的投影、保留被暂停的数据；不擅自改其他领域。 |
| SaveApplication | 原始备份 → 所有计划预检 → 投影的完整存档校验 → 装配 → 正常保存。导入文件与本地读取必须走同一流程。 |

活动进度和暂停内容分开保存。暂停区保存来源插件、领域、稳定实体身份、原记录和暂停原因，参与结构/体积校验但不参与游戏执行；导出必须带上它。它不是“存档坏了”，也不是直接删除数据。

- **道具**：原生口袋里的插件道具、插件专属口袋暂停；金钱与原生道具原样保留。登记快捷键失去目标时取消活动引用，保留恢复记录。
- **宝可梦**：插件物种暂停保管；原生物种上的插件招式、持有道具、特性/形态由育成适配器分别处理，保留被卸下的数据。不能为解除依赖整只删除原生宝可梦，也不能凭空赠送替代宝可梦。
- **地图与移动**：插件地图或失效移动模式中的玩家返回本体安全落点；落点通过有效地形/占位校验。保留原坐标与模式，但重新启用后不自动把正在玩的玩家强行传回去。
- **世界与 Actor**：暂停不可解析的角色、对白引用和覆盖记录。只包含原生数据、已经成功提交的永久世界改动可以继续生效；不能猜测所有未知坐标修改都应该回滚。后续写入需要记录来源才能提供准确撤销。
- **剧情、机关、时间、设施**：停用需要缺失定义的会话/任务/设备，保留其恢复记录；主线旗标和原生时钟不回退。恢复点必须稳定，不能从半场战斗或一半事务继续。
- **插件自有记忆**：现有 dormant `extensions` 继续保留，不因停用清空。重新启用只读取自己的记录。

重新启用时按领域恢复，检查定义版本、UID、容量与目标有效性；冲突/满容量的条目留在暂停区并说明原因，不能覆盖玩家停用插件后获得的新进度。当前不做历史版本迁移，也不默认热卸载：游戏外切换、重启后解析存档。

真正损坏的数据（非法金额、非法 UID、坏 JSON 等）仍须报错和保留原文，不能借“插件恢复”洗成合法新档。

**验收必须走真实链路**：无插件保存 → 启用测试插件并取得内容 → 保存 → 关闭 → 从同一存储加载 → 原生进度仍在 → 行走/交互/保存 → 再加载 → 重新启用，暂停记录可恢复且不覆盖新进度。至少覆盖自有记忆、道具、原生精灵附加招式、插件物种/地图/移动、剧情和世界对白；另外覆盖坏档、恢复容量满和预检后段失败。单测不能只把依赖数组清空后断言通过。

## 本轮的小改造

### 地图角色

`native-cast-data.js` 是按地图索引的只读角色数据：对白ID、原始绑定、出现条件、性别差异及条件覆盖。`native-cast.js` 只做统一投影，`native-object-bindings.js` 继续拥有 C 对象身份、坐标和移动绑定。新增地区在数据表添加项，无需在运行函数增加地图 if/else。

出现条件沿原来的原生旗标“是否已设置”语义读取（starter存物种字符串），不改变剧情条件引擎本身的严格比较语义。对白/地图/角色引用在装配时检查，当前不可见的条目也校验。开场两栋房子的专属阶段演出仍由 opening-objects 提供，这次没有把它伪装为全世界通用行为框架。

### 动态挂载位置

```js
const care = api.ui.slot('care', { parent: 'monster.detail', priority: 10 });
const mood = api.ui.slot('mood', { parent: care });
api.ui.region('mood-panel', {
  slot: mood,
  render: view => ({ kind: 'text', text: `个体：${view.context.uid}` }),
});
```

这是实际嵌入父位置的子位置，不是接受任意字符串却不创建容器。父位置必须先注册，禁止悬空/循环；最多128个自定义位置、12层，排序稳定。新位置可以追加布局与菜单入口；不能借新位置获得替换原生控件的权限，replace/hide 仍限定已有原生控制区。

### 剧情输入与古辰镇

浏览器键盘/触屏/持续输入在剧情接管时清掉移动意图，但不改导演正在播放的动作；选择框导航仍保留。MovementApplication 的输入重置也保护剧情姿态。

眼镜男按只读 `data/maps/OldaleTown/scripts.inc` 的 BlockWestEntrance/FootprintsMan/BlockedPath 校准：获得实验室礼物前站 `(1,11)` 朝左；西出口 `(0,10)` 玩家退右一格，男子上前、保持朝左右移、警告，再下/左回位；解除后恢复源坐标 `(8,9)` 朝右。本项目此处用 `pokedex` 代表实验室授予图鉴的出图进度，已拿初始精灵不等于冒险解除。初始摆位使用绑定后的placement，在首帧前生效；剧情中继续由导演移动，不用持续projection抢占动作。

## 后续执行顺序与边界

1. **存档可继续（P0，已完成当前领域）**：解析、暂停区、同一加载管线、安全落点和冲突恢复已接线。后续新增持久领域必须接入适配器；本轮优先顺序按用户调整为音乐、地图名、存档。
2. **可观测与交互**：点击容器、只读战斗代表例、原生详情页真实挂载例、保存状态反馈；维护公开类型与可执行例。
3. **农场底层**：通用 Actor/device 占位通知、随机数所有权、容量政策。写最小测试插件，不实现完整农场产品。
4. **规则与质量**：按规则族迁出 Gen3默认依赖，补已转写区域差异检查/运行接线检查，明确各闸门的覆盖范围。一次完成一族并记录证据，不反复回归未修改领域。

业务仍通过数据/插件编写；每个扩展点必须同时有注册校验、真实调用、失败反馈、生命周期和至少一个行为测试。源码、公共合同、对应领域文档和 Skill 同步。此计划没有授权大规模重写战斗内核，也不把全绿测试当成完全复刻。
