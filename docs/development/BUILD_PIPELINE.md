# 源码、生成输入与部署构建

2026-10-06落实。`dist/`只有构建产物，不作为作者或导入器的写入位置，也不进入Git。浏览器的文件路径、插件目录清单、内容manifest及ES模块相对引用保持原状。

## 输入所有权

| 目录 | 内容 | 如何修改 |
| --- | --- | --- |
| `src/` | 手写引擎、包、适配器、插件、页面；内容清单、剧情、可编辑的地图/物种等数据；字体与许可 | 修改源码/内容；结构化内容中的原作字段继续按ownership受控导入 |
| `generated/` | grid/tileset JSON、生成的规则/资源模块、PNG、音频、来源记录、测试地图 | 修改工具、配置或只读原作输入，然后预演/重新生成 |
| `dist/` | 前两者同路径复制后的部署树及`.build-manifest.json` | 只构建；不编辑、不入库 |

可编辑地图元数据仍包含受导入器管理的原作字段，它不是纯手写文件。此处保留现有字段所有权与字节保留合同，不谎称把所有混合字段都分类成了纯生成文件。密集网格、图集、PNG和生成JS已物理分开；未来需要逐字段拆分元数据时使用明确内容片段合同，不引入隐式后加载覆盖。

`generated/`作为可携带的派生输入保留在Git：干净检出不需要参考仓库、Pillow或音频渲染器才能构建/测试。重导入才需要相应原作和工具。资源许可、来源修订及哈希随输入携带。

## 构建与验证

`npm run build`只组装已提交输入，不重新导入原作、不压缩模块、不改规则。Node标准库即可完成；无需新增打包器。构建枚举两棵输入树，拒绝同一部署路径重复、源符号链接与保留输出名。先在独立临时树复制全部文件，完成后换入`dist`；普通拷贝/更换失败保护上一份构建。全量物化自然清除已删除输入留下的旧文件。

构建清单对每个输出记录源路径和SHA-256；没有时间戳或本机绝对路径。同一输入产生相同字节与清单。`npm run build:check`只检查现有构建，拒绝过期输入、改写/新增/缺失的输出。它不会替你修复产物。

`npm run dev`先构建。开发服务器在处理静态请求前检查源路径/mtime/大小，在锁内重建有变化的输入，继续服务`dist`；失败返回503并在终端显示原错误。当前不提供自动刷新浏览器。`npm run check`、核心/插件/覆盖率测试先构建，测试仍导入实际部署模块，避免只验证源码却遗漏组合产物。单独调用其他质量子命令或Node测试前先运行构建。

## 导入和资源工具

[ImportSession](../../tools/imports/context.py)默认使用[源投影](../../tools/workspace.py)：把`src`和`generated`组合成临时只读视图，候选写入仍暂存。完整候选经过同一校验；正式提交映射回唯一输入所有者。已存在的内容片段按其原位置写回，新grid/tileset片段进入`generated`，新作者内容/manifest进入`src`，生成模块和图片进入`generated`。两棵树的同路径冲突在加载前拒绝。

`--check`只报告候选，不写输入或`dist`。显式`--target`仍支持独立的可部署输出包，用于转换/测试；它不改变项目的源码布局。字段越权、坏引用和普通写入故障回滚仍沿用原合同。新作者字段不能被无关导入格式化。

UI导出、骑乘素材导出默认写`generated`；音频安装通过同一源投影读取、向`generated`安装模块/资源，并向`src`更新目录/可编辑地图。原作和`sources`始终只读。

## Review与迁移验收

业务修改看`src`，工具/配置看`tools`，派生变化看`generated`；构建目录不参与review。`.gitattributes`标注派生树便于GitHub折叠，但它不是写入权限或正确性校验的替代。

验证包括：无参考资料的构建、相同输入二次构建一致、删除输入清除输出、重复路径拒绝且保留旧构建、产物篡改检测、导入预演不写源码/产物、源路由与越权拒绝；其余领域及插件通过原测试入口复查。相关证明见`tests/build.test.js`与`tools/tests/test_source_layout.py`。
