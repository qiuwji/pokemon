# 如何验证，又不重复消耗

测试的目的是证明公开合同和参考行为，不是每次重跑所有旧证明。先从[当前验证记录](../project/VALIDATION.md)找到相关证据，列出本次改变的规则、接线、保存或资源。只有这些范围和依赖边界需要重查；阶段最终收口才运行系统和真实浏览器回归。

## 选择最小有效范围

| 改动 | 必要证明 |
| --- | --- |
| 新内容定义 | 注册/目录引用有效，公开入口一次正确执行；错误引用拒绝 |
| 新规则阶段或状态 | 实际战斗时机、目标/来源、次数/到期/离场；相关PP、RNG和成本不半写 |
| 新事务/奖励/物品 | 成功提交、后段失败回滚、容量失败、稳定奖励去重及保存恢复 |
| 新世界/Actor行为 | 通行/碰撞/预约、入图与重载、非法位置不半写；涉及时间时查跨日/离线政策 |
| 新UI/表现 | 查询与命令接线、纯时序、取消/reducedMotion/释放；浏览器输入/焦点/可见结果另外观察 |
| 保存或公共合同 | 当前schema、坏档/缺插件原文保护、重绑、公开类型及受影响路由 |
| 仅文档/Skill | 链接、元数据、与实际源码匹配；新增可执行例运行一次，不顺带重跑整个游戏 |

写测试用真实注册器、应用服务、命令总线和领域状态，尽量通过公开入口。只替代不可控时钟、宿主播放、浏览器端口等外部依赖；不要mock整个战斗/设施后再断言mock返回值。测试准备可以设置精灵/旗标/位置，但要明确那是夹具，不能算原作剧情已演过。

断言可观察结果：状态增减、选择分支、事件顺序、目标身份、成本、保存恢复以及失败前后。避免只检测文件字数、实现函数被调用或字符串存在来证明玩法。架构守卫可检查结构，但不是行为证据。

## 一个完整失败证明

[validation.test.js](../../examples/validation.test.js)先排队合法奖励，再排队不存在个体的亲密度意图；执行真实插件事务后断言钱、奖励账本、插件记忆和RNG都未变化。它还检验只读查询和重载。若文件更名，搜索`late invalid intent`或`Core intent rejected`。这是故障边界例，不是所有命令都已验的承诺。

[共享测试夹具](../../tests/helpers/session.js)使用生产catalog和应用服务，仅固定时钟、存储和UI；一次`session()`创建隔离实例。默认session是已完成开场的中期场景，fresh:true保留新游戏位置，但仍添加战斗伙伴与rescued旗标；验证真实新游戏时需明确移除这些安排。自建插件/天气/时钟夹具要显式声明场景、开场旗标与位置，不能假设PACK.start一定是未白镇或户外。只统计本次操作的事件时，先截取准备场景后的事实基线；读档测试保留已加载位置，不强行再进默认场景。`settle()`让后台启动的剧情完成；超过有限次数报错，不用无限等待隐藏锁问题。

## 如何运行及处理失败

在项目根运行`node --test examples/某项.test.js`或对应`tests/领域.test.js`。筛选用`node --test --test-name-pattern="关键词" tests/领域.test.js`，保存实际匹配用例数量。Node汇总通过文件但没有匹配case不能算验证成功。

失败后保留命令和原日志，判断是实现、合同还是夹具错，再修正最小范围。不要删断言、skip失败、关闭校验、放宽权限、恢复旧格式来让数字变绿。修复后复查失败项和新增影响范围；无关已经通过的项不再重跑。异步任务未结束时继续观察同一进程，不启动第二份测试。

`npm test`（或`npm run test:core`）只执行tests核心合同；`npm run test:plugins`单独执行examples作者示例和已安装插件清单检查，`test:examples`是其别名。`npm run test:all`显式执行两组。`npm run check:docs`检查Skill代码块与文件完全一致，并检查项目本地Markdown链接、导入索引/所有权/入口文件的一致性；示例改动后必须同步Skill。元数据校验使用接手工具已有Skill校验器，或按普通YAML frontmatter确认name/description；不要把流程绑定到某个模型专属工具。

## 核心与产品插件隔离

核心测试验证引擎、应用服务以及插件宿主公开合同，不依赖任何已安装产品插件。共享装配在tests/helpers/session.js，最小扩展定义在tests/fixtures/extensions/；这些夹具不部署。架构守卫禁止tests导入src/plugins、generated/plugins或examples，新增核心合同测试也遵循这一边界。

产品插件业务用例放examples/的独立.test.js文件，登记插件时补对应测试；撤下产品插件时一并撤下其专属用例。保留通用宿主失败、权限、事务和保存测试，不靠skip或忽略缺模块掩盖问题。examples/catalog.test.js专门验证实际装配清单，空清单是有效状态。

## 静态质量检查

`npm run check`已串联`check:lint`与`check:engine-types`，CI沿用同一入口。ESLint覆盖src/generated、测试、示例和工具MJS，检查未定义名称、未使用导入/局部变量、重复键等；浏览器和Node全局按目录区分。未使用参数/捕获异常、主动拆除字段的rest绑定及以下划线命名的弃值是显式政策，不通过批量禁用规则掩盖缺陷。删除未使用绑定时必须保留有副作用的调用、随机数消费与测试断言。

`tsconfig.engine.json`当前以checkJs/strict检查剧情变量、动画轨道和精灵帧采样三个真实JS模块。`tests/engine.typecheck.ts`含正确用法与`@ts-expect-error`反例；若接口误放宽，反例会因不再报错而失败。新增范围逐模块补JSDoc，不改为any或关闭strict换取通过，也不把消费方d.ts检查宣称为全部JS已检查。

## 证据记录

写到`docs/validation/日期-主题/manifest.json`及同目录日志。至少包括：

- 日期、基线提交、工作树/版本和本次任务范围。
- 涉及源码/示例/资源的hash，固定原作参考路径和修订；项目示例标明非原作。
- 实际执行命令、退出码、匹配数量、通过/失败/跳过，首次失败原因和修复。
- 未执行项（浏览器/完整系统/原作对照等）及证据失效条件。

分批通过不能相加称一次全量通过；历史556项系统基线仍是历史结果。生成新manifest，不修改旧证据hash或旧截图来冒充当前版本。源码、保存、命令/生命周期政策或资源变更只使相关证据失效。日志不要含个人存档或凭据。

## 框架阶段最后一次系统与浏览器验收

收口时分别执行`npm run test:all`和`npm run check`，避免再重复同等全量。覆盖率需求时以`npm run test:coverage`替代核心测试，插件组仍独立执行；覆盖统计src运行时模块，不把测试文件计入产品覆盖。CI分别运行check、核心覆盖率和插件测试，固定只读参考用于文档链接；本地通过不代表远端CI已经运行。记录实际结果，不预填测试数。

浏览器沿正常入口验输入/朝向、连续地图与门转场、剧情自动移动/选择、代表训练家战斗、非战斗设施、详情互动、Actor、保存重载、触屏与reducedMotion、真实资源音频。至少让内容作者完成一次“新区域→机关→分支剧情→训练家→奖励→保存重载”，记录被迫改核心的缺口。

浏览器不得直接写window.game或localStorage制造通过；准备场景可用正常存档导入，但说明输入来源。启动服务、HTTP200、纯canvas截图或无浏览器dispatch不能证明实际点击和表现。没有观察到的项目写未验证；全作地图/剧情/设施内容按独立还原清单继续开发。
