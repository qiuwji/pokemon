# 剧情、道具与战斗演进（v0.4）

这一轮先完成引擎扩展入口的统一，再继续制作内容。

- 剧情：`StoryEngine` 按触发点、条件、前置事件和单次标记选择事件，返回演出指令；`CommandRunner` 等待对话、行走、镜头和转场结束，最后提交完成记录。事件依赖检查缺失引用与环；事件按声明顺序匹配。任务手记来自条件表。
- 奖励：统一 `reward` 指令，稳定 ID 记入领取账本。先检查整份奖励再一次提交钱、物品、标记；重复执行不再领取。剧情选择不写队伍、标记或金钱。捕获入队改成独立命令并按精灵 UID 去重。
- 道具：`ItemService` 使用定义中的场景、目标和效果，先在目标草稿试算，再扣数量和提交。伤药、好伤药、解毒药、精灵球与超级球共用入口；球倍率传入捕捉规则。无效操作不扣道具、不改变随机种子、不消耗回合。
- 招式：唯一 `MoveEffectRegistry` 包含 primary/beforeDamage/afterDamage/secondary 阶段。`executeMove` 仅编排行动；`EffectRegistry` 提供操作，回复和解除状态同时供招式、道具复用。扩展定义覆盖同一个注册表，不再走回退 if-else。未知名称和参数明确报错；已登记但未实现的复杂效果禁用选择并保留数据。
- 规则：创建个体策略、倒下后强制替换是否占回合、状态概率与回合伤害集中到 policy；计算规则可注入。地形行为码移到具名解码模块。
- 会话：战斗事件只复制演出需要的字段；NPC 状态属于实例，消失角色会清理，读档或重开会释放旧会话。
- 合同：新增编辑器可读的 JSDoc/声明文件与运行时校验；尚未把整个项目迁移成 TypeScript，也未声称完成所有原作机制。

新增剧情时，在内容包事件表注册事件（id/trigger/requires/after/once/build），在 build 中复用已有演出命令；奖励使用稳定 ID 的 reward。新增道具时只添加定义，背包、目标选择和商店自动读取它。新增特殊运算时注册一个操作，再在效果定义中引用。

v0.4 曾迁移旧标记；v0.5 按用户授权移除本作旧档迁移，当前开发存档版本为 3。长演出不保存执行游标，失败不会回滚已完成的领域操作，奖励去重可以防止恢复时重复领取；当前不支持从动画中间继续。

验证：原有 55 项检查与新增 14 项边界检查通过；浏览器验证旧存档导入、通用背包、解毒与恢复流程。插件宿主按 docs/history/implementation-p0-p7.md 的 P6 实现；v0.5 队伍与席位合同见 docs/architecture/BATTLE.md。
