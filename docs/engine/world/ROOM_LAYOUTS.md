# 持久房间布局：秘密基地扩展合同

**设计规格，尚未实现。** 本页给后续框架开发者划定接口与验收范围；没有新增可调用的注册种类、命令或保存字段。当前可用接口仍以[世界状态](STATE_AND_LIFECYCLE.md)、[野外行动](../field/FIELD_ACTIONS.md)和公共类型为准。完整秘密基地的入口、装饰目录、获得剧情与访问规则属于后续业务。

## 为什么不能只用现有接口拼接

现有`core.world.patch`可一次提交多条格子/对象覆盖并保存；对象可移动，但没有家具朝向、多格占位、放置区域和房间布局所有者。它保护玩家、持久Actor及移动预约，不等于已经校验所有家具间的重叠。

插件store可保存自有数据，却不能与另一次world.patch命令原子提交；当前插件事务intent没有worldPatch。不能先写store再改地图，并声称读档和失败时必然一致。设施会话在活动中禁止保存、退出后只保存结果，也不能充当长期房间布局。[设施合同](../facilities/FACILITIES.md)仍负责活动，不承接房间编辑。

## 核心名词与所有权

- **布局定义**：可编辑区域、固定入口、放置政策及可用家具目录；不包含玩家实例。
- **家具定义**：具名方向的格子占位、通行属性、渲染引用和交互声明；旋转选择明确存在的变体。
- **房间实例**：稳定ID、定义引用、修订号及家具实例集合；LayoutService是唯一持久所有者。
- **世界投影**：由布局推导的格子、占位与可交互对象，只读且可重建，不是第二份存档布局。
- **编辑计划**：基于expectedRevision及当前真实占位准备的一次增删移动/旋转计划；提交前再次校验。

依赖方向：插件定义/命令 → 应用编辑用例 → 布局与库存/世界端口 → 提交事实 → 查询/表现。通用布局领域不导入绿宝石、DOM、Actor实现或剧情。绿宝石政策负责装饰分类、限制和原作差异。

## 拟议公开合同

下列是待实现的合同形状，不是现有API。开发时同步公共类型、权限、内容依赖与实际接口名字；插件作者暂不能调用它们。

| 入口 | 输入与职责 |
| --- | --- |
| 家具注册 | name、方向变体、每变体的footprint/通行/视觉引用、交互声明；启动校验资源及重复格 |
| 布局注册 | map、编辑区域、保留入口/不可编辑格、可用家具、参数schema、可选纯放置政策 |
| 创建/绑定房间 | 定义ID与稳定实例ID；同区域只允许一个有效房间投影所有者 |
| 编辑命令 | room、expectedRevision、操作列表；place/move/rotate/remove，以家具实例ID定位 |
| 查询/预览 | 冻结实例、合法变体、当前修订、投影；预览只给结果和拒绝理由，不可当提交令牌 |
| 事实事件 | 提交后的room/修订/变更实例；动画或音效失败不撤销已提交布局 |

坐标沿用地图格子和高度合同，不引入另一套像素坐标。footprint用相对锚点的显式格集合；每格声明占位和通行，地面毯与实体柜子可采用不同政策。旋转通过变体映射，不自动旋转贴图后假定碰撞正确。不支持旋转的原作装饰只注册一个变体。

家具实例只存id、definition、x/y、variant和合法参数。数量/归属若来自道具，调用唯一库存的扣除/返还计划；不另存“背包家具数量”。纯装饰内容无需伪造宝可梦或Actor身份。交互复用注册式野外行动，通过稳定布局对象ID路由，不让field-director识别某家具名称。

## 空间投影与原子提交

1. 以基础地图及当前永久覆盖建立只读底图；布局投影在永久覆盖之上，visit覆盖在布局之上。宿主明确该优先级，不能依注册顺序猜。
2. 家具占位进入统一world.cells、碰撞、移动预约、Actor导航及交互查询；不能仅在Canvas画出来。房间内预约两端均要保护。
3. 受管理区域中的冲突world.patch拒绝。非冲突覆盖仍允许，但必须校验最终投影；未实现这一接线前不能开放可碰撞家具。
4. 编辑校验所有目标格：边界/区域、高度、允许地形、入口、家具间政策、玩家/Actor/预约，以及业务定义的出口可达政策。可达性是布局政策，不对所有地图强加同一规则。
5. 一次编辑列表先生成完整候选布局和库存计划，整体失败则修订、库存、RNG、世界和事件均不变。不要逐条提交后靠反向操作补救。
6. 提交检查expectedRevision及空间条件仍有效，再同步提交领域状态与唯一库存；提交期间无await。投影由已提交布局派生。保存和通知在提交后执行，显示错误不能导致重复扣款或奖励。

只有普通位置可编辑时允许提交；战斗、设施、剧情占用该房间或移动未稳定时返回明确资格失败。只读预览可以在忙碌时使用，但结果可能过期。重复请求须携带稳定业务操作ID并走同一提交账本；网络连接内去重不能代替领域去重。

## 保存与生命周期

新增布局保存状态前更新当前保存合同，项目不迁移旧开发档。校验定义/资源依赖、唯一实例ID、修订、区域、方向、footprint与家具归属；缺插件时拒绝读档并保护原文。存档只保存布局，不保存投影、编辑预览、动画或页面对象。

离开地图保留布局、释放编辑锁；重入/读档从保存布局重建投影。移除家具后释放派生占位及交互引用，返还按库存容量规则整体校验。布局重置/房间解除须通过所有者命令，不允许插件直接删除worldState记录。热卸载不在当前宿主范围内，不承诺运行中拔掉家具定义仍可继续。

## 接手实现与验收

框架任务依次实现：纯注册/布局计划 → 保存合同 → 世界统一投影/占位 → 应用原子提交/公共命令 → 插件UI/表现。具体文件按现有模块职责放置；不要在adventure.js堆家具规则，也不要在设施类增加secretBase分支。

首个代表例用独立插件注册房间与两格家具，经公共命令放置→移动→旋转→移除→保存重载；不用先填完整装饰目录。至少证明：

- 两格家具真实阻挡第二格，world.cells和Actor导航读到同一占位。
- 越界、入口受阻、家具重叠、预约冲突和陈旧修订在提交前失败，布局/库存不半写。
- 一次列表后段失败不保留前段；返回背包容量不足时布局仍保持原样。
- 换图/读档重建，缺定义保护原文；事件重试不重复扣除/返还。
- 绘制只消费投影，缩减动态效果及页面关闭不改变布局；浏览器实际编辑另验。
