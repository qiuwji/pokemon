# 插件扩展能力评审与后续工作

2026-10-03 收到用户提供的外部评审。以下是待逐项核对/演进的工作，不把评审文字或接口注册数量当成实现证据。先完成当前 ENGINE_ROADMAP.md 的未完成机制，再在相应合同收口时补扩展点。

## 领域扩展

- 形态：核对有效 HP 与当前 HP 的缩放/恢复、个体派生类型、动态招式映射及共用 PP、回合期限、物种通配资格、世界范围的限次持久化。优先让这些能力成为可声明的形态政策，避免为 Mega/极巨/太晶各自复制领域状态与恢复逻辑。默认 Gen3 规则保持 HP 不变，现代机制由独立插件启用。
- 战斗格式：核对现有多联盟/控制器/席位的真实能力。注册格式描述席位、排列、可选目标与行动政策；布局消费同一只读座位模型。三打的距离与轮盘的轮换需要独立政策，不能仅增加格式字符串。
- 环境：天气、场地、空间分别为不同生命周期/作用范围的规则；电子场地、魔法空间、戏法空间不能当成天气名称加入雨晴表。扩展定义同时约束逻辑、事件、保存和表现。
- 阶段：固定阶段顺序仍由结算内核掌握。先用现有通用时机组合新规则；真实缺少的前后结算节点再定义明确合同和排序，不能允许插件随意重排关键不变量。
- 育成：遗传步骤可配置、来源与结果可查；Gen3 为默认政策，后代传球/跨亲本蛋招式等属于版本化规则包。
- 移动：2D 网格是本工程明确的世界合同；基础/加速模式名称可由内容配置，不因此重写为任意几何引擎。

## 表现扩展

- 战斗演出：注册语义事件的演出处理/阶段，形态切换通过同一合同验证；多击、蓄力与未命中需要可选择分支和多段轨迹，不在导演中写现代机制名称判断。
- 动画轨迹：关键帧、具名缓动、条件分支和参数 schema；计时与渲染分离，缩减动态效果模式保留完整语义。
- 场景：场景注册与对应 renderer 注册必须配套。导演负责生命周期/参数，不负责具体画法；适配器选择可用的 Canvas/DOM/SVG 渲染能力。
- 环境/转场：具名注册表、开始/更新/结束/清理合同。避免可注册定义却必须修改适配器才能显示的新假扩展点。
- 多渲染目标：效果声明所需能力；各宿主适配器管理资源与清理，游戏领域不读取 DOM。

## UI 扩展

- 宿主插槽：注册与声明具体页面区域，队伍/背包/商店/战斗都应能挂接入口与内容；未知插槽在启动时失败，不静默消失。
- 布局：增加 input/checkbox/radio/slider/tabs/list/table 等可访问控件及基础像素样式 token。renderer 和控件 schema 成对注册；限制在本项目可信 JS 模式的明确边界，不声称第三方沙箱。
- 既有页面：提供具名区域与类别提供者，支持添加、隐藏与替换的冲突/排序政策；背包分类、详情页页签和战斗附加操作是组合验收锚点。
- 主题：具名字体、间距、边框、尺寸、动画时长 token；像素风默认主题与缩减动态效果政策保留。不要将任意 CSS 字符串散入领域数据。
- 对话/模态：可注册对话类型与结果 schema，取消、焦点、输入锁与导航由 shell 统一负责。
- HUD：默认内容也应通过同一个组件/槽合同组合，显式允许隐藏/替换，监听查询与事实事件；不复制一份金钱/队伍状态。

## 验收与优先级

优先补经业务实例证明的公开接口缺口，按“复杂 UI 模组”和“形态演出模组”两个组合实例验收。内容作者只能修改插件/内容目录，操作经命令、状态经所有者保存、表现只消费事件；要求卸载/重载清理正确。每一项记录已实现未验证或已验证及失效条件，不在每轮重复全部测试。

这些现代扩展不能充当完整绿宝石的机制验收；原作设施、地图、剧情与音画仍有各自的内容范围与验证依据。
