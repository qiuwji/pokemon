# 存档与停用插件

本合同针对当前开发存档版本，不做旧版本迁移。插件开关是游戏外的启动设置，修改后重启生效。

## 玩家会看到什么

关闭插件后，继续同一份冒险：原生位置、剧情旗标、金额、队伍、库存、时钟与插件自有记忆保留。需要缺失定义的内容进入 `state.suspendedContent`，界面显示暂停条目数；正常保存和导出包含这些记录，不是另开新游戏。

插件物种暂停入库保管，原生精灵只卸下不可用招式、持有道具或特性，特性回到该物种已有的可用定义。图鉴暂停显示缺失物种；重新启用后合并回来。不会为了维持队伍而赠送替代精灵。队伍因此为空时，野外仍可保存和行走，战斗入口继续检查可战斗队伍。

插件地图或失效移动模式使用有效世界投影寻找安全陆地：优先当前原生地图，找不到再到内容包 `PACK.safeReturn`。检查碰撞、水面、单向边缘、传送格和角色占位。原位置/移动模式留在暂停记录，重新启用不自动传回旧地点。

## 代码职责

| 落点 | 唯一职责 |
| --- | --- |
| `src/engine/content-suspension.js` | JSON边界、暂停区合同、领域计划装配、逐条试恢复和整档验收；不知道绿宝石或存储设备。 |
| `src/game/emerald/assembly/save/creature-suspension.js` | 个体UID、队伍/PC/寄养/交换对象、附加招式、特性、持有物及图鉴的暂停/恢复。 |
| `src/game/emerald/assembly/save/runtime-suspension.js` | 库存槽、快捷道具、Actor、外观、遭遇凭证、形态、天气、机关、作物、定时任务、设施结果和剧情会话。 |
| `src/game/emerald/assembly/save/world-suspension.js` | 世界覆盖引用和安全落点；对白等按字段暂停，不覆盖同对象的原生坐标与文字改动。 |
| `src/game/emerald/assembly/save/content-resolver.js` | 内容包装配、当前插件可用性与依赖计算。 |
| `SaveApplication` / `SaveStore` | 启动读取与手工导入使用同一解析器；存储冲突、备份、保存失败与界面反馈。 |

新增一个持久领域时，必须添加其引用处理适配器、暂停负载校验、恢复前置条件和真实保存/关闭/重开测试；不能在 `adventure.js` 或浏览器入口增加插件ID分支。保存契约会验证暂停区，不接受任意根路径写入。

## 恢复与冲突

重新启用时，在分离的草稿上恢复，重新计算活跃依赖并通过完整存档与剧情恢复校验后才采用。恢复有依赖顺序时重试，例如先恢复精灵，再恢复其形态。库存槽只有仍空着才恢复；附加字段只有仍等于暂停后的值才恢复；原生世界字段同理。新的招式配置、道具或剧情会话不会被旧内容覆盖。

队伍满时，返回精灵可进入未满的PC；PC/寄养容量满、UID重复、字段变化或定义版本不匹配时继续保管。部分恢复失败不阻止其余有效记录恢复。图鉴按集合合并。暂停的设施历史、旅行目标列表等整段集合在当前集合已变化时暂不自动合并，保留记录供后续业务处理。位置记录仅供查阅，不自动恢复。

插件自有 `extensions` 记录保留原数据版本，当前启用插件的版本/schema仍严格校验；没有隐式迁移。插件模块自身缺文件、定义错误或声明依赖缺失属于启动配置错误，不在此存档解析器内猜测修复。

## 数据保护与验证

解析前检查有限JSON、暂停区结构和允许路径；缺插件时只处理其命名空间引用，原生非法金额、个体数值、坏JSON或当前启用插件中的悬空引用仍拒绝。缺失插件的私有语义只能在重新启用并取得定义后完整核验，不能声称已验证未安装插件的所有业务规则。

首次采用投影前，`SaveStore` 将原文备份到 `<save-key>:before-content-suspension`，不覆盖已有原始备份；读取/备份写入失败时保护原存档。普通存档键不在加载时改写，只有后续成功保存才替换。手工导入也先备份输入文档。原生非法数据不会因为投影被修正成合法金额；所有失败保留上次成功保存的数据并显示原因。

核心验证入口：`node --test tests/content-suspension.test.js`。包含同一存储启停/保存/重读/恢复、金额和主线保留、缺地图/空中模式、安全落点、字段冲突、PC满、原生坏档、暂停区坏路径和备份失败。各领域既有测试同时验证其暂停合同。测试证据查 [VALIDATION](../project/VALIDATION.md)；实际浏览器由用户验收。

## 多个独立存档（用户指定的网页版功能）

[槽位仓库](../../src/game/emerald/assembly/save/slot-repository.js)归应用装配层：以pack-id作为存储命名空间，旧键直接作为legacy，新增槽位使用独立slot键，目录记录槽位和上次选择。标准Storage端口的getItem/setItem/removeItem负责读写与失败清理，key/length枚举可发现其他页面追加但未出现在目录的槽位。引擎SaveStore不知道菜单或原作规则，状态/envelope版本保持不变。

New/reset先验证并保存新槽位，再写目录；失败不更换现会话，目录失败清理本次新键，旧数据不动。自动保存继续使用会话绑定的SaveStore，其他页面改动目录不能把本页保存重定向到另一槽位；同一槽位仍检查expectedRaw。槽位预览只decode、不load或写备份；界面收到冻结快照。本地core.save.select通过槽位ID和预览原文检查重新加载，再切换目录与重绑会话；原文变化、坏档、容量/访问失败拒绝，plugin/network禁止提交此命令。

导出/导入操作当前槽位，重新开始总是新建，旧内容不因New覆盖。已有坏档仍保留。已被此前版本覆盖且没有导出或备份的旧进度，不能凭新增槽位机制追溯恢复。检查入口：[存档回归](../../tests/save-slots.test.js)、[启动与选择界面](../../tests/launch-flow.test.js)；实际浏览器由用户验收。
