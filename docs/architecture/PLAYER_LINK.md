# 玩家联线：会话、所有权与提交合同

**设计规格，尚未实现。** 当前[NETWORK](NETWORK.md)只提供单机命令控制。这里的房间/联线交易/联线战斗接口尚未注册，不可当现有API调用。完整匹配、交换与联机对战是可选后续业务；没有部署服务器，也不自动连接外部服务。

## 可复用与必须新增的边界

现有WebSocketTransport和loopback是可替换传输端口；schema、有界JSON、命令权限、排队和提交后事件可复用。NetworkGateway的session只是一次控制连接，去重缓存在内存中，断开取消未执行请求，重连不能恢复持久业务提交。

core.trade.prepare/exchange交换的是当前存档中的伙伴池，不是另一个玩家的唯一精灵。不能把远端JSON写进tradePartner后宣称完成联线。玩家联线另有会话/决策日志与领域入口；它不放宽网络命令白名单、不暴露任意存档替换和脚本执行。

## 核心名词与职责

- **玩家身份**：某份本地存档所属的稳定身份；连接ID与显示昵称不代表所有权。
- **房间/epoch**：参与者集合、协议/内容规则协商和会话代次；旧连接消息不得改变新一代会话。
- **提案/操作ID**：需要参与者确认的具体业务操作；跨重连重发仍指向同一决策。
- **权威协调者**：排列输入、保存最终决策和可恢复日志的所有者；可由可替换本地/服务适配器提供，不等同socket对象。
- **领域托管**：本地所有者暂时锁定待交换或参战资源；界面隐藏按钮不是有效托管。

| 模块职责 | 管什么、不管什么 |
| --- | --- |
| 联线协议 | 精确消息schema、大小/顺序/epoch/指纹、可支持能力；不执行战斗规则 |
| 会话服务 | 邀请/加入/确认/离开/恢复、参与者和阶段；不复制世界存档 |
| 协调端口 | 输入排序、持久决策、重连查询；传输只搬运编码消息 |
| 业务注册 | 声明配置/输入/结果schema、资格、准备/应用/取消/恢复政策；插件不能直接修改远端存档 |
| 本地应用服务 | 经精灵/库存/战斗所有者准备及提交；持久托管和去重 |
| UI/表现 | 冻结会话查询、受控行动、事实反馈；不以动画结束决定成交 |

通用会话层不认识绿宝石交换进化、招式、房间名称；这些由注册业务和现有领域服务组合。与单机控制使用独立能力协商和命令空间，不能因为对方连上了socket就获得宿主插件的全部写权限。

## 拟议公开入口与消息

拟议注册入口接收operation定义：参数/输入/结果schema、参与者人数和纯资格政策，配套明确的本地域操作端口。业务登记必须只引用已开放领域能力；未知能力在启动时拒绝，不接受插件提供任意函数写本地save。状态查询和语义事件均为冻结JSON。

拟议受控入口为创建/加入/离开房间、提出/接受/拒绝操作、提交行动、恢复查询。具体API名和权限由实现时的公共类型发布；当前不能调用core.link之类未注册名字。

业务消息的必要字段如下，最终schema须与编码器成对实现：

| 字段 | 含义 |
| --- | --- |
| protocol / type | 联线协议与明确消息枚举；不复用控制协议command承载任意业务 |
| room / epoch / participant | 目标房间、代次与已确认发送身份 |
| id / sequence | 当前消息身份及发送者顺序；与业务operationID分开 |
| operation / baseRevision | 稳定业务身份与依据的会话修订 |
| payload | 对应消息schema的有界数据，不传整份存档 |

启动协商协议、规则包/内容目录摘要和本业务所需能力。未知物种、道具、形态、状态或不一致规则先拒绝提案，不在对战中临时补定义。允许版本差异必须有显式适配政策；本项目不为旧开发档增加兼容。

会话状态建议为invited→negotiating→ready→active→finished；断开进入suspended，只能恢复原操作或执行已有取消决策。每条消息校验阶段/参与者/修订；同ID同载荷返回已有结果，不同载荷拒绝。不能用双方本地时钟谁快决定冲突；顺序来自权威修订。

## 交换：两个存档不能靠两次本地命令原子化

交换先协商有限精灵转移描述和内容依赖。身份用`{player,monsterUid}`，不同存档中的相同UID字符串不得误认同一个体。接收本地身份分配需保存稳定转移映射，重试不会生成第二只。

1. 两端通过精灵/库存所有者校验可转移、队伍底线、容量和当前忙碌状态；持久化托管。托管精灵不能同时存放、进化、出售或再次交换。
2. 各端准备合法接收/交出计划，向协调者确认；未全部准备时只有取消决策可释放托管，不显示完成。
3. 协调者持久写入唯一commit或abort决策及描述摘要，然后各端按operationID幂等应用。已记录commit的操作不能因超时本地取消。
4. 某端掉线保留未完成日志，重连先查询同一操作的最终决策再补齐。没有权威决策可查时维持托管，不凭猜测既返还又接收。
5. 交换进化作为接收后的独立领域事件/合法计划处理，不能让动画失败撤销已完成的交换。

这是可恢复的协调提交设计，**不是现有的跨设备原子保证**。持久协调日志及本地托管恢复没有实现之前，只允许无资产的诊断会话，不对外开放真实精灵转移。消息缓存和“同时点确认”不能替代这两个条件。

## 联线战斗：同步行动而非互相覆盖HP

参与者提交合法战斗行动，引用controller/seat及`{player,monsterUid}`映射；Battle仍拥有联盟、席位、目标、行动顺序和结算。协调者收齐当前回合输入后按确定顺序执行同一规则包，输出带修订的语义事实/快照，表现层各自播放。

不能接受远端指定伤害、捕获结果、HP或随机数。随机源归权威战斗会话，掉线恢复从检查点/决策日志继续，不重抽已决定回合。迟到、重复和错误回合行动拒绝；超时/投降由业务政策产生一次决策。

首期参战使用受托管个体的临时战斗投影，战后不写回经验/金钱/背包，避免复用野外战败剧情。若业务需要道具消耗/奖励写回，另定义结算计划、托管及去重，不能默认同步所有物品。本地多人练习只证明Battle多控制者能力，尚不证明该网络接线。

## 保存、故障与插件生命周期

持久化本地玩家身份、资源托管、稳定操作映射及未完成决策日志；socket、消息回调、动画、连接队列不入档。缺业务插件/内容时保护存档原文并阻止恢复提交，不能释放可能已成交的资源。当前没有热卸载，不能宣称运行中卸载插件能自动撤销跨设备成交。

错误分层：协议错误不进入领域；资格失败不建立托管；准备失败按abort清理；commit后网络/显示失败只触发恢复，不能重放扣款或随机生成。事件在本地领域提交后发出，显示“待对方恢复”与“已完成”要区分。

## 首个代表例与实现顺序

先做纯协议/会话状态机和loopback双端无资产活动，验证邀请→协商→输入→结果→断开恢复。再做持久日志/托管及真实交换，最后接入Battle行动流。每步用插件公开入口和可替换传输，不要求内容作者修改NetworkGateway、Battle或save validator。

必须验证：旧epoch/乱序/重复载荷冲突、内容不匹配、非参与者、同时接受/拒绝、准备后断开、commit后单端失败、进程重启恢复、容量变化、同UID跨玩家映射、奖励/资产不重复。交换以两份独立存档实际领域状态断言；战斗以同一回合输入和权威事实断言。真实WebSocket与浏览器分别观察，测试peer不能冒充生产协调者。
