# 绿宝石 · 丰缘序章

一个可玩的网页版序章，以及可复用的单人、格子地图、回合制捕捉 RPG 引擎。无前端运行时依赖；所有地图、角色和精灵素材均随网站提供。支持键盘、鼠标与触屏。

## 运行

需要 Python 3 和 Node.js（Node 只用于检查；浏览器运行无需 Node）。

```sh
npm run dev
# 打开 http://localhost:5173
npm test
npm run check
```

也可以把 `dist/` 交给任何能提供静态文件的 HTTP 服务。由于使用 ES 模块与 fetch，不要双击 HTML 以 file:// 打开。

## 当前游玩范围

从未白镇开始，沿北边道路救助小田卷博士。调查博士的背包，选择木守宫、火稚鸡或水跃鱼，击败 Lv.2 蛇纹熊。前往古辰镇和 103 号道路与小遥对战，再返回研究所领取图鉴与 5 个精灵球。

提供 9 张原作地图：未白镇、101 号道路、古辰镇、103 号道路，以及博士研究所、主角家一楼和二楼、古辰镇宝可梦中心和商店。103 号道路的水域在当前没有冲浪的版本不可通行；其他未实现入口会明确提示。

包含：逐格地图渲染、连续道路滚动、NPC 巡走/转向/原地动作、地图碰撞、单向台阶、室内入口、道路连接、NPC 对话、三选一搭档、草丛随机遇敌、攻击/道具/替换/逃跑、捕捉、六人队伍、满员后的电脑盒子、经验/升级/努力值、学习招式选择、部分升级进化、宝可梦中心、购买道具、本机自动/手动存档及 JSON 存档导入导出。图鉴提供 20 个精灵与部分进化形态。

## 分层与复用

本轮将主程序拆成 `engine/`（规则和通用会话）、`presentation/`（动画）、`adapters/`（浏览器宿主）与 `packs/emerald/`（本作剧情、会话、界面）。`app.js` 仅装配这些模块。地图、战斗、存档和剧情指令执行器可在 Node 中运行，UI 的购买、回复、换队、学习、进化与存档操作都通过会话命令完成。

依赖图与扩展步骤见 [ARCHITECTURE.md](ARCHITECTURE.md)。v0.5.0 模块拆分、席位合同与边界见 [BATTLE_ARCHITECTURE.md](BATTLE_ARCHITECTURE.md)，后续目标见 [IMPLEMENTATION_PLAN.md](IMPLEMENTATION_PLAN.md)。

v0.5.0 支持多精灵训练家单打：队伍结束判定、敌方后备、参战者经验分配、主动/强制替换和奖励去重。救助博士后可在 101 号道路挑战带两只伙伴的练习训练家，这是新增验收内容。双打与多阵营实际调度和界面尚待 P2。开发存档版本为 3，不读取旧开发档。

v0.3.0 增加可组合的剧情演出：自动寻路、NPC 靠近与领路、玩家跟随、转身、像素表情、镜头聚焦与回归、等待、并行轨道和黑幕下的场景布置。救助后先在野外交流、跟随离场，再转场到实验室并自动走入；求救、调查背包、治疗、奖励和战败送回也接入相同机制。新增演出只需编排内容指令，详见 [CUTSCENES.md](CUTSCENES.md)。

界面改为本地中文像素字体、硬边双层窗框、游戏画面内菜单。房屋使用遮盖后提交再揭开的转场；道路继续连续滚动；遇敌用交错条带遮盖并播放双方进入。战斗增加攻击、弹道、辅助效果、受击、HP 插值、倒下、换人、回复、投球、晃动、挣脱和捕捉成功演出。减少动态效果模式移除抖动与闪烁。

动画消费规则层的事件快照，不重新计算战斗。当前按招式和属性配置通用演出，尚未逐个复制原作全部招式的逐帧动画。

### 内容接口

- `species[id]`：名称、属性、种族值、捕获率、经验产出、成长曲线、特性、努力值产出、等级学习表。
- `moves[id]`：名称、属性、威力、命中率、PP、先制度、效果标识与附加效果概率。
- `typeChart[攻击属性][防御属性]`：克制倍率，缺省为 1。
- `maps[id]`：尺寸、按行存储的碰撞块与行为数组、双向连接、入口、标牌和素材。
- `evolutions[id]`：当前支持等级条件与目标精灵。
- 事件角色由 `objectsFor(state, db)` 给出；剧情由事件条件、前置依赖、标记和完成/奖励账本驱动。训练家队伍在 `packs/emerald/trainers.js` 定义。

地图块与原作格式一致：低 10 位为 metatile ID，位 10–11 为碰撞，位 12–15 为高度。对于自行创作的地图，可直接填充 `0` 为可走格、`1024` 为阻挡格；行为数组标记草丛、台阶、水域与柜台。地图不使用整张场景 PNG。素材统一保存在 `tiles-{tilesetId}.png` 中，每个单元为 8×8；`tilesets[id].lookup` 把原作图块编号和调色板映射到图集位置，`metatiles` 用 8 个基础图块定义一个含两层的 16×16 地图格，`attributes` 描述遮挡层，`animations` 提供花朵/水面等逐帧图块。各地图只保存格子数组及四格 border，按 `tileset` 引用同一图集。

### 添加地图

1. 在 `content.json.maps` 中添加格子数组，选择已有 `tileset`，或增加 8×8 图块图集和 metatile 定义。
2. 在两侧 `connections` 中声明方向、目标和对齐偏移；入口则通过 `warps` 声明目标地图与目标入口序号。
3. 在剧情包定义 NPC 及事件；添加原作遭遇表或自定义权重表。
4. 增加“重要目标可到达”检查，验证入口/出口、碰撞和台阶方向。

当前转换脚本可从 [pret/pokeemerald](https://github.com/pret/pokeemerald) 导出选定地图、palette、tilemap 和数据。运行脚本会重新生成内容，先备份自定义内容：

```sh
python3 -m pip install Pillow
python3 tools/import-emerald.py /path/to/pokeemerald
python3 tools/import-encounters.py /path/to/pokeemerald
```

脚本顶部的 `map_names` 与 `entries` 定义导入范围。脚本使用研究所、街道等原作数据，并没有加载或执行 ROM。

### 添加招式/规则

招式数据写入 `content.json.moves`；效果由唯一 `MoveEffectRegistry` 以 primary/beforeDamage/afterDamage/secondary 阶段组合注册操作，不再接受返回 true 的旧处理器接口。未知效果和错误参数提前报错，已登记但未实现的复杂效果禁用选择。道具的恢复与解除状态使用同一基础效果注册表，见 [ENGINE_EVOLUTION.md](ENGINE_EVOLUTION.md)。

`Battle` 装配队伍、行动、回合、招式、结果和事件服务，计算规则由 `rules` 注入。事件携带席位集合、来源/目标 UID 和精简独立快照；`duelView` 投影到单打画面，动画不计算伤害。

### 存档

格式为 `{ version, savedAt, state }`，导出另含 `pack` 标识。当前版本 3。存档包含精灵个体值/努力值/性格/经验/招式 PP、队伍、盒子、道具、当前位置、标记与随机种子。读取时检查版本、精灵和招式引用、地图边界等基础结构。

开发期间升级版本可拒绝旧存档；稳定发布后再建立迁移承诺。通用 SaveStore 支持注入迁移器，本包不配置。跨内容包应使用独立存档键。当前存档仅属于当前浏览器与站点来源；本地预览与上线网址属于不同来源，需要使用导出/导入转移进度。

## 原作一致性与明确差异

参考数据来自 [pret/pokeemerald](https://github.com/pret/pokeemerald)，伤害和捕捉实现参考其中 `src/pokemon.c`、`src/battle_script_commands.c`，遭遇表来自 `src/data/wild_encounters.json`。

已采用第三世代的类型决定物理/特殊分类（例如恶属性特殊、幽灵属性物理）、种族值/IV/EV/性格数值计算、招式 PP/威力/先制度、STAB、属性克制、2 倍暴击、85–100 随机伤害系数、低体力初始精灵特性、部分能力等级、捕捉四次判定、原作早期草丛精灵分布与等级。

这是序章切片，不是完整的逐帧模拟或百分之百一致的 ROM 复刻。当前差异/待办：

- 从镇外出发，省略搬家、调时钟等开场演出；NPC 台词与任务手记为适配网页版重新编写。
- 双方队伍单打；敌方随机选择招式、按队伍顺序补位，原作训练家 AI、双打及多阵营调度尚未实现。
- 随机数使用可存档的 JavaScript PRNG，与原作 RNG 序列不同。遭遇采用原作基本概率，暂省略变换地形的抑制、部分步数/特性/道具修正。
- 常用低等级攻击与能力变化已实现；完整天气、所有特性、持有道具、全部复杂招式效果尚未实现。原作伤害运算完整修正及极端整数舍入不承诺逐位一致。
- 状态涵盖战斗内部分异常，尚未复刻全部场外效果及所有抵抗/特性联动。
- 进化仅实现已收录的部分等级进化；刺尾虫分支进化等尚未实现。
- 首战失败时仍由博士救回并赠送搭档；普通战斗失败在中心恢复。赔钱公式是当前切片规则，未完整复制原作流程。
- 当前音效是简短合成提示音，不是原作配乐。没有道馆、完整徽章、联盟、双打、骑车、冲浪或联机。

后续按 [实施计划](IMPLEMENTATION_PLAN.md) 完成双打、完整特性/持有道具、移动模式、培育/复杂进化，再稳定插件宿主和网络命令入口。

## 连续地图与 NPC

道路连接由 `SceneGraph` 预先放入同一全局网格。相机跟随精灵的插值坐标，按可视范围同时绘制当前地图和相邻地图；跨越边界仅改变当前位置的地图引用，世界坐标继续移动一格，不重置画面。室内入口属于不同区域，在完全遮盖画面后提交目标地图，再淡入。

`GridMotion` 在一格移动期间锁定方向，走路与跑步分别采用 160ms/96ms。帧表严格遵循原作：朝下 0/3/4、朝上 1/5/6、朝左 2/7/8；朝右镜像对应朝左帧。跑步使用独立的原作 running 图集，不混用朝向。

`NPCSystem` 从内容声明读取 wander/look/jog/still 与范围，保存各角色当前格、目标格及动画进度。目标和出发格在移动期间都被保留，避免重叠；对话/菜单/战斗暂停巡走，调查角色时会朝向训练家。环境随机数与战斗随机数分离。

中文界面采用本地 [Fusion Pixel Font](https://github.com/TakWolf/fusion-pixel-font) 12px 简体字形，按 SIL OFL 1.1 提供，字体与上游组件许可随 `dist/assets/licenses/` 一起保留。原作地图和角色图像仍来自 pret/pokeemerald；新增战斗粒子与精灵球由像素绘图代码生成，并非完整原作动画素材。

本轮新增 17 项剧情演出检查：命令整树校验、并行冲突与失败汇合、镜头插值、独立内容包复用、背包四个方向的救助回程、入口遮盖提交、剧情走路抑制遭遇、失败释放控制、存档边界与战斗交接。浏览器实际完成求救、选伙伴、击败蛇纹熊、博士靠近、自动跟随离场和实验室进场，并确认结束后存档可重新读取。

### v0.6.0 双打与本地多阵营

救助博士后，在 101 号道路东侧和练习员互动。双打及三阵营需要至少两只可战斗伙伴。每只伙伴分别选择行动，选完才执行整个回合；可重选尚未执行的行动。招式目标菜单可选择敌方或友方，群体招式按内容定义自动结算。
